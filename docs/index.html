The Problem

Small models choke on big schemas

The traditional approach: dump an entire API schema into a system prompt and ask the model to fill it all at once. Works for GPT-4. Fails for anything under 7B.

Monolithic — today’s approach

One giant prompt, one giant failure

The model sees a 2,000-token system prompt with every field, every option, every type constraint. It hallucinates keys, gets formats wrong, invents values. 12% accuracy on a 3B model.

# system prompt (2,471 tokens) POST /api/print/start { "mode": "generate|file|library" "filament": "PLA|PETG|TPU|ABS" "scale_mm": number (5-500) ... 11 more fields ... } # model output (hallucinated): "mode": "3d_print" # not valid "scale": 80 # wrong key
FormedSkill — one field at a time

Minimal context. Maximum reliability.

Each LLM call handles exactly one field: the question, the hint, and the valid options. Even a 3B model handles this reliably. The framework assembles the final payload.

# step 1 of 6 (190 tokens) Q: What type of job? Options: generate | file | library Hint: User describes -> generate A: "generate" ✓ # step 2 of 6 (160 tokens) Q: Describe what to print A: "dragon figurine" ✓ # 4 more fields -> 100% accurate

How It Works

Form-filling for LLMs

FormedSkill treats tool calling like filling out a paper form: one field at a time, with clear labels and valid options. The framework handles the rest.

01

Load a skill YAML

Define your API fields, types, options, and hints in a single YAML file. Supports text, numbers, options, booleans, JSON arrays, and conditional fields (show_when).

02

One LLM call per field

Each extraction is a minimal prompt: the user’s original message, one question, one hint, and the valid options. No schema noise. No hallucination surface.

03

Conditional fields skipped automatically

show_when: "mode == generate" skips irrelevant fields. The model never sees questions that don’t apply to the current request.

04

Batched mode parallelizes extraction

Independent fields are extracted in parallel — cutting wall time below the monolithic baseline while keeping accuracy at 100%.

05

Payload assembled and dispatched

Collected values are type-coerced, alias-resolved, and assembled into the final API payload. HTTP, shell, or tool_call — you choose the action type.

The Forge Command

Generate skills from existing prompts

Already have a Hermes skill in Markdown? formedskill forge reads it and generates the YAML definition automatically.

zsh — formedskill forge
$ formedskill forge ~/.hermes/skills/media/snailprint/SKILL.md Reading skill: snailprint... Analyzing action and field structure... ✓ Detected action: POST http://localhost:7780/api/print/start ✓ Extracted 8 fields from description ✓ Generated SKILL.yaml → ~/.hermes/skills/media/snailprint/ $ formedskill run ~/.hermes/skills/media/snailprint/SKILL.yaml "Print me a dragon in black PLA, 80mm" --model nemotron-cascade-2 --mode batched ◆ mode → generate ◆ prompt → dragon figurine ◆ filament → PLA ◆ color → black ◆ scale_mm → 80 ◆ printer → auto ✓ Dispatched · 6.1s · 100% fields resolved
Get Started

Zero required dependencies

Works with any OpenAI-compatible endpoint: Ollama, MLX, vLLM, or the real OpenAI. Install in 30 seconds.

Quick install

# minimal pip install formedskill # with better YAML parsing pip install "formedskill[yaml]"

From source

git clone github.com/Snail3D/formedskill cd formedskill pip install -e .

Run a built-in skill

formedskill run formedskill/skills/snailprint.yaml \ "Print a dragon in black PLA" \ --model nemotron-cascade-2 \ --endpoint http://localhost:11434 \ --mode batched

Forge a skill from Markdown

# convert existing Hermes skill formedskill forge YOUR_SKILL.md # validate any skill YAML formedskill validate YOUR_SKILL.yaml
